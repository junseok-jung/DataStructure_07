1.희소 그래프 (간선이 적을 때): 인접 리스트 승 (메모리 적게 씀, 탐색 빠름)

밀집 그래프 (간선이 꽉 찼을 때): 인접 행렬 승 (메모리 역전 현상 없음, 탐색 속도 일정함)
2. 희소 그래프(Sparse Graph) 분석 결과
간선이 적은 희소 그래프(간선 100개)에서는 인접 리스트가 훨씬 효율적입니다.

메모리: 인접 행렬은 간선 유무에 상관없이 무조건 10,000칸 크기의 배열 공간을 차지하여 빈 공간 낭비가 심합니다. 반면, 인접 리스트는 실제 존재하는 간선(100개)만큼만 노드를 만들면 되므로 메모리를 크게 절약할 수 있습니다.

실행 속도:

특정 정점과 연결된 이웃을 모두 찾을 때, 인접 행렬은 무조건 100칸을 전부 확인해야 합니다 (비교 100회).

하지만 인접 리스트는 해당 정점에 연결된 노드만 확인하면 되므로, 평균적으로 2회 내외의 비교만으로 훨씬 빠르게 탐색을 완료합니다. 간선이 적을 때는 삭제나 연결 확인 시에도 인접 행렬과 속도 차이가 거의 나지 않습니다.

3. 밀집 그래프(Dense Graph) 분석 결과
간선이 빽빽한 밀집 그래프(간선 4,000개)에서는 '인접 행렬'이 훨씬 효율적입니다.

메모리: 간선이 많아지면 인접 리스트는 노드를 8,000개(무방향 왕복)나 생성해야 합니다. 노드를 만들 때는 다음 노드를 가리키는 '포인터 화살표' 공간이 추가로 필요하기 때문에, 간선이 일정 수준 이상 많아지면 배열만 사용하는 인접 행렬보다 오히려 메모리를 더 많이 소모하게 됩니다 (메모리 역전 현상 발생).

실행 속도:

인접 행렬은 간선이 아무리 많아도 2차원 배열 인덱스(matrix[u][v])를 통해 단 1번의 비교만으로 삽입, 삭제, 연결 확인을 즉시 처리합니다.

하지만 인접 리스트는 연결을 확인하거나 삭제할 노드를 찾을 때 리스트를 처음부터 순차적으로 탐색해야 하므로, 평균적으로 80회 가까이 비교를 수행하게 되어 처리 속도가 급격히 느려집니다.

4. 최종 결론
본 실험을 통해 그래프의 밀도(간선의 수)에 따라 적합한 표현 방식이 다름을 확인했습니다.

인접 리스트 선택: 정점 수에 비해 간선 수가 적은 도로망이나 SNS 친구 관계 같은 희소 그래프를 다룰 때 메모리를 아끼고 탐색 효율을 높이기 위해 사용합니다.

인접 행렬 선택: 정점 간 연결이 매우 빽빽한 밀집 그래프를 다룰 때나, 두 정점이 연결되어 있는지 빠르게(단 한 번 만에) 확인해야 할 필요가 있을 때 사용합니다.


간선이 많은 밀집그래프에서 인접 리스트의 메모리 사용량이 역전하는이유: 인접 행렬은 정점 수에 따른 고정적인 배열만 사용하지만, 인접 리스트는 간선마다 동적으로 노드를 생성하여 다음 노드를 가리키는 포인터(next)에서 추가적인 메모리를 사용하기 때문입니다.

두 정점의 연결여부를 확인할 때도 인접행렬이 유리한 이유 : 인접 리스트는 해당 정점의 처음부터 순차적으로 탐색해야 하지만 인접 행렬은 2차원 배열의 인덱스 접근을 통해 O(N)의 시간만에 확인 할 수 있기 때문입니다.
